# 4.9.1 完整面评原文及槽位候选

状态：组 A 新独立确切来源候选。继承已冻结 OA 窄修与组 B 初审身份，不覆盖旧候选或根仓库 runtime。生产仍为 BASELINE 的原 server/engine；本目录不是已上线镜像。

招聘 fresh 消息入口使用受支持 text/post AST 的 V1 完整投影。逐行节点直接拼接，不去重；原始字符串和完整投影在截断前计算 SHA，媒体/未知节点/删除线/多语言/未知字段/解析失败/完整标志缺失均待核。求职者所有可见槽位必须完整消费，检测用 NFKC 与全部 Cf 剥离仅用于拒绝，不修复接受英文/空/残缺姓名。同一消息副本的资格字段漂移、多人共享来源与初审双值冲突仍冻结。

语法仅接受一个明确本人姓名、颜值/表现力各一次有限数值及精确末行结果。语法 text_ready 只是原文线索资格，不能成为最终面试通过、不通过或 offer 推进；正式事件、本人评审与完整指纹绑定仍属未完成组 C。最终 passed、groupEvaluatedCount/groupPassedCount 均 null，并另列文本线索计数。唯一完整来源的初审 OK/No 保留；未知/不完整来源的总人数和受影响日期数为 null，不拿缺失当 0。独立实际入职日期与历史事实不删除。

完整后续评审扫描保留撤回/不可读记录，同源编辑、同名或无法证明无关的后续正文均取消 provisional text_ready，保留源 ID 和历史指纹。实际 getChatMessages 招聘入口不再把完整正文放入共享缓存；原 cache 不能恢复旧绿色资格。非招聘显示/缓存/筛除路径不变。两处 current 状态与两处日历 advanceStage 增加明确最终绑定 gate，因此本候选不会以页面 current 或日历线索冒充完整判定。

候选尚未构建完整镜像、切生产、启用提醒、消费 OAuth、读取真实私聊/教练正文、写正式班表、重发消息或代办真人节点。组 C/D/E、跨周期、完整发送账本门禁、真实 OA/旧通知链接、旧同卷 RW 隔离、新鲜停机恢复备份和保留最新业务数据回滚仍 NO-GO。4.9.2—4.9.4 与五环节真人闭环不由本目录测试证明完成。

QA 与 Git 交付结果以 QA-RESULT.json 和本轮主报告为准。源 SHA 见 SOURCE-PINS.json；独立审查和范围证据见 INDEPENDENT-REVIEW.md、FINAL-REVIEW.md、scope-independent.mjs。只归档代码、合成测试和小型证据说明，不提交生产账本、真实正文、环境/令牌、测试日志或备份。BASELINE 中的现场快照为本地证据指针，不在 Git 包内，不由它推断未来发布许可。
