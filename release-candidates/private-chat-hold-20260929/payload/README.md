# Private authorization one-use isolation: source-only paired candidate

This payload is not an active server image, a production cutover or real business acceptance. It contains the three paired private reader/HTTP/page candidates, their exact observed originals, and isolated source regressions. Do not deploy just one component or replace the broader Calendar server with a local Git build.

The private reader keeps the original factory parameters, five public methods, four requested scopes, AES-GCM v2 context and fixed two-person conversation. Authorization-code and refresh POSTs retain the original JSON v2 endpoint and S256 callback. A synced, read-back, no-secret intent plus non-stealable lock precedes a one-use POST. An unknown grant/identity/save/cleanup result blocks cached reads and subsequent exchanges in the same or restarted reader. Normal nonrotating GET failures release the lock. Code TTL, refresh expiry and nondecreasing time are rechecked after intent I/O, immediately before POST. No reset, hold-clearing, refresh-retry or permission-expanding endpoint is added.

The HTTP adapter snapshots trusted configured actors/readers, verifies normal central OA identities against the existing directory verifier, strictly consumes all five status fields, rejects held/busy/unknown state, projects fixed public text, and never forwards identity/expiry/token diagnostics. A provider success is not accepted without strictly consistent authorized result and status readback. Async actor/status deadlines do not cancel underlying I/O; preflight is not atomic permission. The reader lock and persistent intent remain the final barrier. A purely pre-POST local pending link can expire only after a fresh known-safe reader status and no local in-flight operation; this never clears a reader hold, lock or grant.

The actual page retains the observed layout/CSS, fixed participants and scope facts. Its script treats booleans and status enums strictly, prevents duplicate actions and stale results, checks the official authorize URL, shows fixed safe text, and does not unconditionally reopen buttons after failure. An explicit fresh read-only status is the only UI recovery path. Synthetic DOM checks are not browser/OA visual acceptance.

Run `node qa-entry.mjs` from this exact single-level payload. It verifies every byte pin and inventory, runs eight reader source-comparison groups, then the independent reader/HTTP/page and paired native-FS/toy-provider TAP suites. All provider identities/tokens/messages are synthetic. VM filesystem fault tests do not themselves prove actual crash durability; native FS on Windows does not test Linux parent-directory fsync. Tests of old counterexamples preserve their unsafe observation as evidence, not a passing safety claim.

Persistent disk repair can fail: local quarantine remains, but cross-process repair is not guaranteed under continuing storage faults. Synchronous `begin()` on a fresh instance can still construct a URL; paired HTTP preflight and reader `complete()` must enforce the hold before any code POST. Do not treat a URL as a resolved hold. Recovery of an existing hold needs a separately verified operational process, not repeated consent or automatic deletion.

Original message/pagination shape gaps remain deliberately unchanged in this narrow increment: `has_more` truthiness, absent message IDs, cursor type and non-user/missing sender completeness are not authoritative assessment evidence. The existing 120-day predicate bounds the requested span rather than independently proving source age. Neither this package nor `readMessages().complete` validates OA dual assessment conclusions, four coach permissions, full scheduling writeback, real notification receipts or completed five-stage business work.

Before any production cutover, recheck the current full CAS, sources/recipients, dormant same-volume RW isolation, fresh stopped complete backup and tested restore/latest-data rollback, actual OA and old-link pages. Do not touch formal data, replay unknown OAuth/message results or fabricate person actions. Production switches and original release archive records are intentionally excluded here.
